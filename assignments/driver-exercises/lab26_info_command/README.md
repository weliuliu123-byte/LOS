# Lab 26 — Special `info` Command

## 1. Overview

This lab extends the Lab 02 Linux Character Device Driver by implementing a special `info` command.

When userspace writes exactly `info` to `/dev/lab2`, the driver generates a statistics report and stores it in the device buffer.

The report can then be retrieved through the standard `read()` system call.

## 4. Implemented Features

### 4.1 Special Command Recognition

The driver recognizes the following command:

```text
info
```

The command must contain exactly four bytes.

Command detection:

```c
if (len == 4) {
    if (copy_from_user(cmd, buf, 4))
        return -EFAULT;

    cmd[4] = '\0';

    if (memcmp(cmd, "info", 4) == 0) {
        /* Execute info command */
    }
}
```

Commands are case-sensitive.

| Input | Behavior |
|---|---|
| `info` | Execute special command |
| `INFO` | Normal data |
| `Info` | Normal data |
| `info\n` | Normal data |
| `information` | Normal data |

Only `info`, `INFO`, and `info\n` were explicitly verified in the recorded QEMU tests. The remaining behaviors follow from the implemented matching conditions.

### 4.2 Statistics Generation

When the `info` command is detected, the driver generates a formatted report using `scnprintf()`.

The report includes:

- Driver name
- Buffer capacity
- Cumulative successful open count

Example:

```text
LAB-02 Driver Statistic
Driver name: lab2
Buffer size: 1024 bytes
Open count : 3
```

The output is stored in `device_buffer`.

The number of generated bytes is stored in `buffer_len`.

### 4.3 Normal Write Operation

If the input does not match `info`, the driver performs a normal write operation.

Example:

```bash
echo -n "hello lab26" > /dev/lab2
```

The driver stores:

```text
hello lab26
```

The existing read callback can retrieve the data.

### 4.4 Mutex Protection

The shared device buffer and statistics are protected by:

```c
static DEFINE_MUTEX(lab2_mutex);
```

The command response is generated while holding the mutex.

This prevents other operations from modifying the shared buffer during response generation.

### 4.5 Statistics Snapshot

The response is generated when the `info` command is processed.

It is not regenerated automatically when userspace subsequently reads the device.

For example:

```text
write("info") -> open_count = 3

read()        -> open_count = 4
```

The stored report still contains:

```text
Open count : 3
```

This demonstrates snapshot-based reporting.

## 9. Key Takeaways

### 9.1 Command Processing

A device driver can interpret data received through `write()` as commands rather than simply storing it.

This provides a basic command-response interface.

### 9.2 Safe Userspace Access

`copy_from_user()` is required when reading user-provided memory in kernel space.

The return value indicates the number of bytes that could not be copied.

### 9.3 Command Matching

`memcmp()` compares raw bytes.

Checking both command length and content prevents inputs such as `information` from being interpreted as the `info` command.

### 9.4 Formatted Output

`scnprintf()` safely generates formatted strings within a specified buffer capacity.

Its return value can be used to update `buffer_len`.

### 9.5 Shared State Protection

A mutex protects shared device data against concurrent modifications.

### 9.6 Snapshot Semantics

The driver generates statistics during command execution.

Subsequent reads retrieve the stored response rather than recalculating current statistics.

## 10. Limitations

- Command matching is case-sensitive.
- Only the exact four-byte `info` command is recognized.
- Normal data and command responses share the same buffer.
- Executing `info` overwrites previously stored normal data.
- The response is global rather than private to each open file instance.
- Concurrent multi-process command testing has not been performed.
- The exact exercise requirements should be checked against the original assignment if additional command semantics are required.
